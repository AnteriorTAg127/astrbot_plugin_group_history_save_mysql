## 2. 数量模式指令

- **2.1 `/消息总结 50` 正常出合并转发**
  - 【前置】测试群在 `summary_group_whitelist` 中；群内最近有 ≥50 条消息；总开关开。
  - 【操作】群内发送 `/消息总结 50`。
  - 【预期】收到**一条合并转发**，展开后：
    - 第 1 节点为统计信息：`消息总数：…`、`参与者：… 人`、`时间跨度：…`、`活跃排行 Top N：…`、`数据源构成：MySQL x + OneBot y`；
    - 其后为 4 个板块节点，标题依次为 `📢 重要通知与结论` / `💬 讨论要点 / 争议` / `🎉 有趣片段` / `✅ TODO / 待跟进`；
    - 节点文本为纯文本（无 `#`/`**`/`>` 等 Markdown 残留）；
    - 节点署名为 bot QQ（或兜底 `10000` / `总结助手`）。

- **2.2 别名 `/总结 50`**
  - 【前置】同 2.1。
  - 【操作】群内发送 `/总结 50`。
  - 【预期】行为与 2.1 完全一致（同一 handler）。

- **2.3 缺参 / 非法参数 → 用法提示**
  - 【操作】依次发送 `/消息总结`、`/消息总结 abc`、`/消息总结 0`。
  - 【预期】每次回复 `用法：/消息总结 <数量>，如 /消息总结 512`，不触发 LLM 调用（日志无总结流程）。

- **2.4 超上限拒绝**
  - 【前置】`summary_max_count` 保持默认 1000。
  - 【操作】发送 `/消息总结 1001`。
  - 【预期】回复 `最大支持 1000 条，请调整参数`，不出总结、不调 LLM。

## 5. 限流（双冷却）

- **5.1 用户维度冷却（默认 60s）**
  - 【前置】冷却配置默认（user 60 / group 120）。
  - 【操作】用户 A 发 `/消息总结 50` 成功后，**立即**由同一用户 A 再发一次。
  - 【预期】第二次回复 `操作太频繁，请 N 秒后再试`（N ≤ 60）；等待 N 秒后重试成功。

- **5.2 群维度冷却（默认 120s）**
  - 【操作】用户 A 成功后，**立即**换用户 B 在同群发 `/消息总结 50`。
  - 【预期】B 被拒，剩余秒数 60 < N ≤ 120（命中的是群冷却而非用户冷却）。

- **5.3 非法参数不消耗冷却**
  - 【操作】先发 `/消息总结 abc`（用法提示），紧接着发合法的 `/消息总结 50`。
  - 【预期】合法调用正常执行，不被冷却拦截（盖章只发生在参数校验通过后）。

## 6. 混合数据获取（MySQL 优先 + OneBot 补齐）

  - 【预期】统计节点 `数据源构成：MySQL 20 + OneBot 0`；日志无 `get_group_msg_history` 调用痕迹。

- **6.2 新群 MySQL 为空 → OneBot 补齐**
  - 【前置】换一个**从未采集过**的群（或清空其 MySQL 记录）并加入白名单。
  - 【操作】`/消息总结 50`。
  - 【预期】
    - 正常出总结，`数据源构成：MySQL 0 + OneBot ≤50`；
    - 日志可见 OneBot `get_group_msg_history` 调用记录；
    - 若协议端不支持该 action：收到 `该范围内没有可总结的消息` 且日志含降级原因（OneBot 补齐失败原因），**不崩**。

- **6.3 时间模式窗口过滤**

  - 【操作】`/消息总结时间 1h`（群内消息多为 1 小时以前）。

- **6.4 忽略名单生效**

  - 【操作】`/消息总结 50`。
